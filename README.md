# File Tagger

*한국어 · [English](README.en.md)*

특정 디렉토리의 모든 파일/서브디렉토리를 읽어, 사용자가 정의한 **태그 및 태그값**을
파일·디렉토리에 부여하고, 그 태그를 기준으로 **정렬·필터·탐색**을 돕는 데스크톱
애플리케이션입니다.

## 주요 기능

**스캔 · 태그**

- 관리할 루트 디렉토리를 선택해 파일/폴더를 스캔하고, 폴더마다 관리 방식(폴더만 /
  내부 / 재귀)을 정해 인덱싱 범위를 조절
- 라벨 / 텍스트 / 숫자 / 날짜 / 링크 / 이미지 값 유형의 태그를 파일·폴더에 부여
- 파일 크기·수정 시각·이미지 해상도 등은 **시스템 태그**로 자동 부여되어 사용자
  태그와 똑같이 필터·정렬에 쓰임
- 파일을 옮기거나 이름을 바꿔도 태그를 따라 붙이는 이동 추적, 실시간 파일시스템 감시
- 스크립트·외부 도구가 태그를 조회·추가·수정·제거할 수 있는 **명령줄 도구**,
  태그를 폴더 사이로 옮기는 **내보내기·가져오기** (아래 "외부 앱 연동" 참조)

**보기 · 탐색**

- 목록 / 아이콘 / 자세히 세 가지 보기 모드(모드마다 따로 기억되는 확대·축소)
- 태그 조합 **필터**, 태그값 기준 다단 **정렬**, 태그값·폴더 계층으로 묶는 **그룹**
  — 세 가지 모두 칩으로도, 자동완성이 붙는 텍스트로도 편집
- 분할 프리뷰, 썸네일, 키보드만으로 하는 목록 탐색·태그 수정

**커스텀 썸네일**

- "링크" 태그로 워크스페이스 안의 다른 항목을, "이미지" 태그로 바깥의 이미지 파일을
  노드 썸네일로 지정. 여러 태그를 우선순위 목록으로 두어 항목마다 맞는 출처를 고름

앱의 **도움말 보기**(F1)에 사용법·활용 팁·기능과 단축키·시스템 태그 설명을 모아 두었습니다.
도움말 메뉴에서 원하는 탭으로 바로 열 수 있습니다.

## 기술 스택

- **Flutter** (멀티플랫폼 GUI, 데스크톱 우선: Windows / Linux)
- **Drift** (SQLite) — 태그 영속화
- **Riverpod** — 상태 관리

## 태그 저장 방식

태그 데이터는 관리 대상 디렉토리 루트의 `.filetagger/` 폴더 안 SQLite DB에
저장됩니다. 폴더를 이동·복사하면 태그도 함께 따라갑니다. 앱 전역 설정(최근 연
폴더, 테마, 표시 언어)만 태그 DB 바깥에 따로 보관하며, 그 위치는 배포 형태에 따라
다릅니다.

- **포터블판**(압축을 풀어 쓰는 형태): 실행 파일과 같은 폴더. 폴더째 옮기면 설정도
  함께 따라갑니다.
- **설치판**: 계정별 OS 애플리케이션 데이터 폴더.

같은 PC에서 두 형태를 함께 쓰면 설정이 서로 갈립니다(의도된 동작입니다). 또한
설정 파일을 쓸 수 없는 자리에서 실행하면 — 읽기 전용 매체에 둔 포터블판이나 권한이
없는 폴더 — 앱은 그대로 동작하되 **설정이 이번 실행 동안만 유지**되고, 상태표시줄에
"설정이 저장되지 않는 중"이 표시됩니다. 설정을 몰래 다른 위치에 대신 쓰지는 않습니다.

## 외부 앱 연동

### 태그 내보내기 · 가져오기

목록에서 항목을 고르고 '파일 → 태그 내보내기…'(또는 우클릭)를 누르면, 고른 항목의 태그가
명령 파일 **하나**로 저장됩니다.

받는 쪽은 둘 중 하나로 받습니다 — 앱에서 **'파일 → 태그 가져오기…'**로 그 파일을 고르거나,
`filetagger_cli import <파일>`로 읽히거나. **판정은 같은 코드가 하므로 결과가 갈리지
않습니다.** 이미지를 함께 내보냈다면 파일 옆의 이미지도 같이 옮겨야 붙습니다.

- 내보낼 태그는 **고른 항목이 실제로 가진 태그**만 후보로 뜨고, 기본은 전체 선택입니다.
- **태그값 포함**을 끄면 태그만 붙고 값은 비어 갑니다.
- **이미지 파일 포함**을 켜면 커스텀 썸네일 이미지를 내보낸 파일 **옆에** 함께 씁니다.
  두 파일을 같이 옮겨야 이미지가 붙습니다(상대 경로를 그 파일이 놓인 폴더 기준으로 찾습니다).
- 태그가 없으면 만들도록 값 유형·다중 허용·색을 함께 싣습니다.
- 링크 값은 대상의 경로(키워드는 이름)로 풀어 나가고 `missingLink: keep`이 붙습니다 —
  **대상을 함께 옮기지 않았어도 값이 남아**, 받는 쪽에서 '미해결 링크'로 기다립니다.
- 시스템 태그는 담지 않습니다(자동 파생이라 받는 쪽이 거부합니다).

가져오기는 **적용되지 않은 항목만** 펼쳐 보입니다. 스캔이 아직 잡지 못한 파일은 거부가
아니라 **보류**로 남으므로, 스캔한 뒤 같은 파일을 다시 가져오면 그때 붙습니다 — 이미 붙은
것이 두 번 붙지는 않습니다.

### 명령줄 도구 (`filetagger_cli`)

**명령 한 줄로** 태그를 다룹니다. 스크립트나 파일 관리자의 사용자 명령에서 쓰라고 둔
것으로, 앱과 **같은 코드**로 판정하므로 결과가 갈리지 않습니다.

포터블판에는 `cli/bin/` 안에 들어 있습니다. 직접 빌드하려면 저장소에서
`dart build cli`를 돌리면 `build/cli/<플랫폼>/bundle/bin/`에 나옵니다
(`dart compile exe`로는 만들 수 없습니다 — 네이티브 sqlite가 함께 담겨야 합니다).

`bin/`과 그 옆의 `lib/`는 **한 쌍입니다** — 네이티브 sqlite를 실행 파일 기준 상대 경로로
찾으므로, 실행 파일만 떼어 다른 곳에 두면 실행할 때 라이브러리를 찾지 못합니다. 옮길 때는
**번들 폴더를 통째로** 옮기고 PATH에는 그 안의 `bin`을 등록하십시오. 라이브러리를 실행 파일
옆이나 시스템 디렉토리(`System32`, `/usr/lib` 등)에 따로 두는 것으로는 해결되지 않습니다.
리눅스에서 공용 `bin`에 걸고 싶다면 실행 파일을 복사하지 말고 심볼릭 링크나 래퍼 스크립트를
두십시오.

#### 명령

표면은 **명사와 동사**로 갈립니다. `tag`는 태그 **정의**를, `list`는 파일에 붙은
**부여**를 다루고, 둘 다 같은 네 동사를 갖습니다.

| 명령 | 하는 일 |
| --- | --- |
| `tag add <이름> <값 유형>` | 태그 정의를 만든다. 같은 이름·값 유형이 이미 있으면 그대로 둔다 |
| `tag modify <이름>` | 이름·값 유형·다중 허용·색을 고친다(적은 것만 바뀝니다) |
| `tag delete <이름>` | 태그 정의를 지운다. 그 태그의 부여도 함께 사라진다 |
| `tag show [이름]` | **사용자가 만든** 태그 정의를 낸다. 이름을 주면 그 하나만 |
| `list add <대상> <태그> [값]` | 태그를 부여한다. 다중 부여를 허용하는 태그면 값이 하나 더 붙는다 |
| `list modify <대상> <태그> [값]` | 그 태그의 기존 부여를 걷어내고 준 값 하나로 둔다 |
| `list delete <대상> <태그> [값]` | 부여를 뗀다. 값을 주면 **값이 같은 부여만**, 주지 않으면 그 태그 전부 |
| `list show <대상>` | 대상에 붙은 태그를 낸다 |
| `list show --filter <조건>` | 조건에 걸린 **대상들**을 낸다(`--sort`·`--group`으로 차례와 묶음) |
| `scan` | 관리 폴더를 훑어 인덱스를 맞춘다 |
| `import <파일>` | 내보낸 명령 파일을 읽어 그대로 적용한다 |
| `image <이미지 파일>` | 바깥 이미지를 캐시에 등록하고 캐시 키를 낸다 |
| `status` | 인덱스에 들어 있는 노드·키워드·태그의 수를 낸다 |
| `systemtags` | 조건에 쓸 수 있는 **시스템 태그**와 그 성질을 낸다(관리 폴더가 없어도 됩니다) |
| `config show` | 지금 서 있는 콘솔 설정과 설정 파일의 자리를 낸다(관리 폴더가 없어도 됩니다) |
| `config set <키> <값>` | 콘솔 설정 하나를 적는다 |
| `config unset <키>` | 콘솔 설정 하나를 지운다 |

`<대상>`은 **관리 폴더 기준 상대 경로**입니다(`--keyword`를 주면 키워드 이름). 대상을
하나씩 지목하는 대신 `--filter`로 **집합을 지목**할 수도 있습니다 — 그때는 위치 인자가
한 자리 밀립니다(`list add --filter "<조건>" <태그> [값]`).

**태그를 만드는 입구는 `tag add` 하나뿐입니다.** `list`는 없는 태그를 지목하면
거부합니다 — 부여하는 자리마다 "없으면 만들어라"를 함께 적게 두면 같은 태그가 부르는
곳에 따라 다른 성질(값 유형·다중 허용)로 태어나기 때문입니다. `tag add`는 같은 이름·값
유형이 이미 있으면 아무것도 하지 않고 성공하므로, 스크립트 앞에 그냥 두고 쓰면 됩니다.

값 유형은 `label` `text` `number` `date` `link` `image` 여섯입니다.

**시스템 태그는 `tag show`에 섞이지 않습니다.** 파일에서 파생되는 고정 목록이라 만들 수도
고칠 수도 없고, 부여 수 같은 열이 뜻을 갖지 않기 때문입니다. 그 목록은 `systemtags`가 냅니다 —
코드가 쥔 값이라 **관리 폴더를 열지 않고** 어디서든 물어볼 수 있습니다.

#### 옵션

**모든 명령**이 아래 셋을 받습니다(`--workspace`는 관리 폴더를 여는 명령만).

| 옵션 | 뜻 |
| --- | --- |
| `-C, --workspace <경로>` | 관리 폴더. 주지 않으면 `workspace` 설정, 그것도 없으면 현재 디렉토리 |
| `--json` | 사람이 아니라 기계가 읽는 출력 |
| `--lang <언어>` | 콘솔이 낼 언어. 설정보다 이 자리가 이깁니다 |

**판정을 내는 명령**(`list add`·`list modify`·`list delete`·`import`)은 인덱스가 대상을
모를 때 스스로 훑을 수 있습니다.

| 옵션 | 뜻 |
| --- | --- |
| `--auto-scan` | 인덱스가 대상을 모르면 한 번 훑고 다시 판정한다 |

**표를 내는 명령**(`tag show`·`list show <대상>`·`systemtags`·`config show`)은 첫 줄에
열 이름을 냅니다. 기계용(`--json`)에는 붙지 않고(키가 이미 같은 일을 합니다), 경로만 내는
`list show --filter`에도 붙지 않습니다(줄 하나가 그대로 다음 명령의 인자라서). 파이프에서
걷어 내려면 `tail -n +2`를 쓰면 됩니다.

`tag add` · `tag modify`:

| 옵션 | 뜻 |
| --- | --- |
| `--multiple` | 한 파일에 여러 번 부여할 수 있게 한다 |
| `--color <#RRGGBB>` | 칩 표시색 |
| `--rename <새 이름>` | (modify) 태그 이름을 바꾼다 |
| `--type <값 유형>` | (modify) 값 유형을 바꾼다 |
| `--clear-color` | (modify) 표시색을 지운다 |

`list`:

| 옵션 | 뜻 |
| --- | --- |
| `--keyword` | 대상을 경로가 아니라 키워드 이름으로 읽는다 |
| `--value-keyword` | 링크 값을 경로가 아니라 키워드 이름으로 읽는다 |
| `--create-keyword` | 지목한 키워드가 없으면 만들어 진행한다 |
| `--keep-link` | 링크 대상을 못 찾아도 원문을 미해결 링크로 남긴다 |
| `--filter <조건>` | 조건에 걸린 대상 전부에 적용한다 |
| `--auto-scan` | 인덱스가 대상을 모르면 한 번 훑고 다시 판정한다 |
| `--sort <기준>` · `--group <기준>` | (show) 낼 차례를 정하고 묶는다 |
| `--system` / `--no-system` | (show) 파생되는 시스템 태그를 함께 낼지 |

**조회하는 명령**(`tag show`·`list show`·`systemtags`)은 낼 수량을 정할 수 있습니다.

| 옵션 | 뜻 |
| --- | --- |
| `--top <수>` | 앞에서 이만큼만 |
| `--tail <수>` | 뒤에서 이만큼만 |
| `--range <시작>:<끝>` | 이 자리부터 저 자리까지(1부터 세고 양끝을 포함) |

셋은 **하나만** 쓸 수 있습니다. 있는 것보다 많이 달라거나 범위가 끝을 넘어가도 오류가 아니라
낼 수 있는 만큼만 냅니다 — 목록의 길이는 부르는 쪽이 미리 알 수 없는 값이라, 그것을 맞히지
못했다고 명령이 실패하면 스크립트가 늘 개수를 먼저 세어야 하기 때문입니다. 시작이 목록을
넘어가거나 끝이 시작보다 앞이면 아무것도 내지 않습니다. 묶어서 낼 때(`--group`) 세는 것은
**맨 윗줄들**입니다.

`--help`로 전체 목록을 볼 수 있습니다.

#### 스캔을 시키지 않고 붙이기 (`--auto-scan`)

콘솔은 시키지 않으면 훑지 않으므로, 방금 만든 파일에 태그를 붙이면 **보류**로 끝납니다
(종료 코드 `75` — "스캔이 먼저 필요합니다"). `--auto-scan`을 주면 그때 스스로 한 번 훑고
같은 명령을 다시 판정합니다.

```bash
# 파일을 만들고 곧바로 태그를 붙인다(scan을 따로 부르지 않는다)
filetagger_cli -C ~/그림 list add 2026/새그림.png 출처 pixiv --auto-scan
```

- **보류에만 걸립니다.** 거부는 훑어도 같은 자리에서 걸리고, 조건에 아무것도 안 걸린 것은
  훑을 이유가 아니라 조건의 답입니다. 단 `--filter`로 집합을 지목할 때는 **고르기 전에**
  훑습니다 — 조건이 딛는 것이 인덱스라, 뒤늦게 훑어서는 애초에 고르지 못한 것을 되찾을 수
  없기 때문입니다.
- **다시 판정하는 것은 한 번뿐입니다.** 두 번째에도 보류라면 훑어도 잡히지 않는 자리라
  되풀이해야 답이 같습니다.

전체 스캔은 값이 큰 일이라 **기본이 아닙니다**. 파일을 여럿 다루는 스크립트라면 `scan`을
한 번 부르고 나머지를 붙이는 쪽이 훨씬 쌉니다.

#### 콘솔 설정 (`config`)

명령마다 적기 번거로운 값의 **기본값**을 적어 둡니다.

| 키 | 뜻 |
| --- | --- |
| `lang` | 콘솔이 낼 언어. `--lang`을 주지 않은 실행이 이 값을 씁니다 |
| `workspace` | 기본 관리 폴더. `-C`를 주지 않은 명령이 이 폴더를 엽니다 |

이 목록은 `config --help`와 `config set --help`가 설명과 함께 냅니다 — 무엇을 적을 수
있는지 물으러 다른 곳을 볼 필요가 없습니다.

언어는 명령이 돌기 전에 먼저 읽으므로 `--help` 문구까지 그 언어로 나옵니다.

**설정 파일은 실행 파일 옆에 둡니다.** 이 도구는 PATH에 걸어 두고 부르는 것이라, OS마다
다르고 찾아가기 어려운 자리를 둘 값이 없습니다(GUI의 포터블판과 같은 자리 규칙이고, GUI와
담는 것도 겹치지 않습니다).

**범위마다 파일이 하나씩**입니다 — `cli.json`이 이 바이너리를 부르는 모두에게,
`cli.<계정 이름>.json`이 그 계정에만 걸립니다. 계정별이 전역을 덮습니다.

```json
{ "lang": "ko", "workspace": "/home/사용자/그림" }
```

파일이 곧 범위라 안에는 설정 이름과 값만 적습니다. 겹쳐 담지 않는 것은 나중에 설치판이
생겼을 때 **계정별 파일만 쓸 수 있는 자리로 옮겨 가면 되게** 하려는 것입니다 — 한 파일에
겹쳐 두면 그 파일 하나가 두 자리에 있어야 합니다.

우선순위는 키마다 넷이고, **마지막 자리만 다릅니다** — 아무도 정하지 않았을 때 기댈 곳이
언어는 OS이고 관리 폴더는 명령을 부른 자리입니다.

```
--lang  >  계정별 설정  >  전역 설정  >  OS 설정 언어
-C      >  계정별 설정  >  전역 설정  >  현재 디렉토리
```

```bash
# 지금 서 있는 값과 설정 파일의 자리를 본다
filetagger_cli config show

# 지금 계정에만 적는다(범위를 주지 않으면 여기)
filetagger_cli config set lang en

# -C를 매번 적지 않도록 기본 관리 폴더를 적어 둔다(상대 경로는 펴서 적힙니다)
filetagger_cli config set workspace ~/그림

# 이 바이너리를 부르는 모두에게 적는다
filetagger_cli config set lang ko --global

# 지운다 — 아래 범위(또는 OS 설정·현재 디렉토리)로 넘어간다
filetagger_cli config unset lang
```

사람이 열어 고칠 수 있는 JSON이라 손으로 고쳐도 됩니다. 계정을 가리키는 이름은 OS가 알리는
계정 이름이며, `config show`가 그것과 두 파일의 자리를 함께 냅니다.

**적는 기본이 계정별인 것**은 한 기계를 여럿이 쓸 때 적는 사람이 남의 설정까지 바꾸지 않게
하려는 것입니다. 환경이 계정 이름을 알리지 않으면 계정별로는 적지 못하고, 전역으로 몰래
옮겨 적지도 않습니다.

**기계가 읽는 것은 언어를 타지 않습니다.** `--json`의 키와 값, 종료 코드, 거부 사유·세부
갈래의 이름, 값 유형 이름은 언어 설정과 무관하게 같습니다. 언어를 타는 것은 사람이 눈으로
읽는 문구와 **시스템 태그 이름**뿐입니다(조건에 적는 이름은 여전히 어느 지원 언어로도
읽힙니다).

#### 조건 — 고르기 · 차례 · 묶기

조건 문법은 **화면의 조건 줄과 같습니다.** 도구모음에서 만든 필터·정렬·그룹 텍스트를
그대로 옮겨 붙일 수 있습니다.

| 옵션 | 쓰는 법 |
| --- | --- |
| `--filter` | `작가==김 -별점<3` — 태그 이름 뒤에 `==` `!=` `<` `<=` `>` `>=` `~`(품음) `!~`. 이름만 쓰면 "붙어 있음", 앞에 `-`를 두면 제외 |
| `--sort` | `별점 작가` — 앞선 기준이 이깁니다. 이름 앞에 `-`면 내림차순, `?`면 무작위 |
| `--group` | `작가 "폴더 계층"` — 태그값으로 버킷을 나누고, 폴더 계층으로 묶습니다 |

- **이름에 공백이 있으면 인용합니다**(`"수정 시각">2026-01-01`). 셸 인용 위에 조건 문법의
  인용이 한 겹 더 얹히는 자리입니다.
- **읽지 못한 조각이 하나라도 있으면 명령 전체가 거부됩니다**(종료 코드 `64`). 오타를
  조용히 버리면 고르는 집합이 뒤집힌 채 명령이 돌기 때문입니다 — `-별점<3`에서 `-` 하나가
  떨어져 나가는 것으로 충분합니다.
- **조건에 아무것도 걸리지 않으면** 쓰기 명령은 거부로 끝냅니다(종료 코드 `65`).

**시스템 태그**(크기·확장자·수정 시각·이미지 크기 등)는 저장된 태그가 아니라 파일에서
파생되는 값이라, 물어볼 때 그 자리에서 계산합니다. 조건에서는 늘 쓸 수 있고, 이름은 어느
지원 언어로 적어도 읽습니다. 목록과 성질은 `systemtags`로 볼 수 있습니다.

#### 스캔은 시켜야 돕니다

`scan`이 **전체 스캔이 도는 유일한 자리**입니다. 다른 명령은 몰래 훑지 않습니다 —
태그 한 줄을 붙이자고 폴더 전체를 훑는 것은 명령 한 번의 값이 아니고, 언제 훑을지는
부르는 쪽이 정할 일이기 때문입니다.

그래서 **인덱스가 아직 모르는 파일**(방금 만든 파일 등)에는 태그가 붙지 않고, 거부가
아니라 "아직"으로 답합니다(종료 코드 `75`). `scan`을 먼저 돌리거나, 앱이 폴더를 열 때·
파일시스템 변화를 감지할 때 도는 스캔을 기다리면 그대로 성립합니다.

전체 스캔은 **겹쳐도 됩니다.** 스캔은 "관측되지 않은 노드는 사라진 것"이라는 판정을
하는데, 그 판정이 노드마다 **마지막으로 관측된 시각**을 함께 봅니다 — 내가 훑기 시작한
뒤에 누군가 그 노드를 보았다면 내가 못 봤다고 해서 지우지 않습니다. 그래서 앱이 훑는
동안 콘솔로 훑어도 서로의 발견을 덮지 않습니다(대신 같은 폴더를 두 번 훑는 값은 듭니다).

#### 앱이 켜져 있어도 됩니다

**그냥 씁니다.** 같은 DB를 여럿이 고치는 것은 SQLite가 알아서 직렬화하고, 떠 있는 앱은
바깥에서 들어온 변경을 스스로 알아채 화면을 고쳐 그립니다(창이 앞에 있는 동안 주기로
확인합니다). 명령을 친 뒤 곧 목록에 반영됩니다.

#### 커스텀 이미지

이미지 태그의 저장값은 관리 폴더 캐시 안의 **캐시 키**(내용 해시로 지은 파일명)입니다.
그래서 값 자리에 놓인 문자열 하나만으로는 "바깥 파일의 경로"인지 "이미 등록된 키"인지
가릴 수 없는데, 그것을 **명령 이름으로** 가릅니다.

- `list add <대상> <이미지 태그> <이미지 파일>` — 바깥 파일 **경로**를 받아 등록까지 합니다.
  상대 경로는 명령을 친 자리 기준입니다.
- `image <이미지 파일>` — 등록만 하고 캐시 키와 관리 폴더 기준 경로를 냅니다. 명령 파일을
  손으로 짤 때처럼 **키만 필요할 때** 씁니다.

#### 출력

기본은 콘솔에서 읽기 좋은 형식으로, 열을 탭으로 가릅니다(`cut`·`awk`로 집어 쓸 수
있습니다). `--json`을 주면 외부 도구·AI가 결과를 받아 다음 동작을 하기 좋은 JSON으로
냅니다.

- `list show <대상>`은 **내보내기와 같은 명령 목록**이라 다른 관리 폴더로 그대로 옮길 수
  있습니다. 시스템 태그는 밖에서 부여할 수 없어 **기계용에서는 빠지고**(사람용에는 나옵니다)
  `--system`으로 뒤집을 수 있습니다.
- `list show --filter …`는 **태그가 아니라 대상**을 냅니다 — 줄 하나가 그대로 다음 명령의
  인자가 됩니다. `--group`을 주면 들여쓴 트리가 되지만 줄마다 경로 전부를 냅니다.
- 쓰기 결과는 그 명령에 `result`(그리고 거부됐다면 `failure`)가 붙은 모양이며, **항목이
  하나여도 배열**입니다 — 받는 쪽이 개수에 따라 모양을 가려내지 않아도 되게 했습니다.

#### 종료 코드

스크립트가 분기할 수 있도록 `sysexits` 관례를 따릅니다.

| 코드 | 뜻 |
| --- | --- |
| `0` | 했다 |
| `64` | 명령을 잘못 썼다 |
| `65` | 명령이 거부됐다(없는 태그, 값 유형 불일치 등 — 사유가 함께 나옵니다) |
| `66` | 관리 폴더가 아니다 |
| `74` | 파일을 읽고 쓰지 못했다 |
| `75` | **아직 안 됐다** — 인덱스가 대상을 모릅니다. `scan`이 먼저 필요합니다 |

한 번에 여러 항목을 다루는 `import`에서는 **거부가 보류를 이깁니다** — 보류는 스캔 뒤
다시 넣으면 서지만, 거부는 다시 넣어도 같은 자리에서 걸리기 때문입니다.

#### 예

```bash
# 태그를 세운다(이미 있으면 그대로 둔다)
filetagger_cli -C ~/그림 tag add 출처 text
filetagger_cli -C ~/그림 tag add 작가 link

# 새로 만든 파일을 인덱스에 넣고 태그를 붙인다
filetagger_cli -C ~/그림 scan
filetagger_cli -C ~/그림 list add 2026/새그림.png 출처 pixiv

# 작가 키워드를 링크로 건다(키워드가 없으면 만든다)
filetagger_cli -C ~/그림 list add 2026/새그림.png 작가 김아무개 --value-keyword --create-keyword

# 붙어 있는 태그를 명령 목록으로 읽어 낸다
filetagger_cli -C ~/그림 list show 2026/새그림.png --json

# 조건에 쓸 수 있는 시스템 태그 이름을 확인한다(폴더가 없어도 된다)
filetagger_cli systemtags

# 콘솔이 낼 언어를 계정별로 정한다
filetagger_cli config set lang en

# 가장 최근에 고친 다섯 개만 본다
filetagger_cli -C ~/그림 list show --sort '-"수정 시각"' --top 5

# 조건에 걸린 것들을 본다(별점 4 이상인 jpg를 별점 높은 차례로)
filetagger_cli -C ~/그림 list show --filter '별점>=4 확장자==jpg' --sort '-별점'

# 조건에 걸린 것 전부에 태그를 붙인다
filetagger_cli -C ~/그림 list add --filter '작가==김아무개' 즐겨찾기

# 조건에 걸린 것을 다른 도구로 넘긴다
filetagger_cli -C ~/그림 list show --filter '확장자==png' | while read -r p; do echo "$p"; done

# 다른 사람이 내보낸 태그를 받는다
filetagger_cli -C ~/그림 import ~/받은태그/filetagger-20260904.json
```

## 내려받기 / 빌드

**Linux**는 릴리즈 페이지에서 포터블 tar.gz를 내려받아 압축만 풀면 됩니다.

**Windows 실행 파일은 릴리즈에 싣지 않습니다.** 코드 서명이 없는 실행 파일을 웹에서
내려받으면 Windows가 SmartScreen 경고를 띄우기 때문입니다. 직접 빌드하면 그 경고 없이
릴리즈와 같은 포터블판을 얻을 수 있고, 아래 절차가 그 방법입니다. Microsoft Store
배포는 준비 중이며, 나오면 그쪽이 더 간편한 길이 됩니다.

> **Flutter SDK 없이 CMake만으로는 빌드할 수 없습니다.** `windows/flutter/CMakeLists.txt`가
> Flutter 툴이 만들어 내는 설정 파일을 읽고, 빌드 도중 다시 Flutter 툴을 호출해 Dart
> 코드를 컴파일하기 때문입니다. 다만 **Visual Studio는 전체 설치 없이 Build Tools만으로**
> 됩니다.

### Windows에서 빌드하기

**1단계 — C++ 빌드 도구 설치**

Visual Studio IDE 전체는 필요 없습니다. **관리자 권한 PowerShell**에서:

```powershell
winget install --id Microsoft.VisualStudio.2022.BuildTools --exact --source winget --override "--passive --wait --add Microsoft.VisualStudio.Workload.VCTools --add Microsoft.VisualStudio.Component.VC.Tools.x86.x64 --add Microsoft.VisualStudio.Component.VC.CMake.Project"
```

설치 관리자 화면에서 직접 고른다면 워크로드 하나와 그 안의 구성 요소 둘입니다. Build
Tools 설치 관리자에서는 **"C++ 빌드 도구"**, Visual Studio IDE 설치 관리자에서는
**"C++를 사용한 데스크톱 개발"** 워크로드이고, 오른쪽 구성 요소 목록에서 **MSVC 빌드
도구**와 **Windows용 C++ CMake 도구**가 켜져 있어야 합니다(기본으로 켜져 있습니다).

**2단계 — Flutter SDK 설치**

[Flutter 공식 설치 안내](https://docs.flutter.dev/get-started/install/windows/desktop)에서
SDK 압축 파일을 받아 원하는 위치에 풀고, 그 안의 `bin` 폴더를 환경 변수 `Path`에
추가합니다. **새 PowerShell 창을 연 뒤** 아래로 확인합니다.

```powershell
flutter doctor
```

`Visual Studio - develop Windows apps` 줄에 체크가 뜨면 1단계가 제대로 된 것입니다.
Android 관련 줄에 경고가 남아 있어도 이 앱을 빌드하는 데는 상관없습니다.

**3단계 — 빌드**

저장소를 받아 그 폴더에서:

```powershell
flutter pub get
flutter build windows --release
```

**추가 인자는 필요 없습니다.** 이렇게 빌드하면 릴리즈와 같은 포터블판(설정을 실행 파일
옆에 두는 형태)이 나옵니다. 버전도 따로 지정할 필요가 없습니다 — Flutter 빌드가
`pubspec.yaml`의 버전을 실행 파일에 새기고 앱이 그것을 되읽어, 정보 창에 보이고
업데이트 확인도 그 값으로 최신 릴리즈와 견줍니다.

**4단계 — 산출물**

```
build\windows\x64\runner\Release\
```

이 폴더가 통째로 한 벌입니다. `filetagger.exe` 하나만 떼어 내면 실행되지 않으므로
**폴더째** 원하는 위치로 옮겨서 쓰세요.

### Linux에서 빌드하기

C++ 도구와 GTK 개발 헤더가 필요합니다(Debian·Ubuntu 계열 기준).

```bash
sudo apt-get install -y clang cmake ninja-build pkg-config libgtk-3-dev liblzma-dev libstdc++-12-dev
flutter pub get
flutter build linux --release
```

산출물은 `build/linux/x64/release/bundle/`에 나옵니다.

### 개발용 실행 · 코드 생성

```bash
flutter run -d windows        # 또는 -d linux
```

개발 실행도 포터블로 잡히므로 **전역 설정이 빌드 폴더 안에 남고, 빌드를 지우면 함께
사라집니다.** 첫 실행 상태를 다시 보고 싶을 때 그 파일만 지우면 됩니다.

생성 파일(`*.g.dart`)은 저장소에 함께 커밋되어 있으므로 **빌드 전에 따로 돌릴 필요가
없습니다.** DB 스키마 등 생성 대상을 고쳤을 때만 다시 만듭니다.

```bash
dart run build_runner build   # 코드 생성 (Drift)
```

로컬라이제이션 코드는 `lib/l10n/`의 ARB에서 Flutter 툴이 직접 생성하며 `flutter pub get`이
다시 만들어 주므로, 손으로 따로 돌릴 것이 없습니다.

## 표시 언어

한국어와 영어를 제공합니다. 기본은 OS 설정 언어를 따르고, **보기 → 언어**에서 언제든
바꿀 수 있습니다. 고른 언어는 다른 머신 단위 설정과 함께 저장됩니다.

영어 문자열은 한국어 원문을 AI의 도움을 받아 번역한 것입니다. 어색하거나 용어가 어긋난
자리를 발견하면 이슈나 PR로 알려 주세요.

## 프로젝트 구조

```
lib/
  domain/        엔티티, repository 인터페이스, 유즈케이스 (플랫폼 무관)
  data/          DB(Drift), 파일시스템 스캐너, repository 구현
  presentation/  Riverpod providers, 화면, 위젯
  cli/           콘솔 명령 표면 (Flutter 없이 도는 진입점)
  core/          공통 유틸, 상수
  l10n/          ARB 번역 파일과 거기서 생성된 코드
```
